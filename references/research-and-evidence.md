# 리서치와 근거

## 조사 여부

최신 시장, 경쟁작, 가격, 성과, 플랫폼 정책 또는 실제 게임 데이터가 문서 결론에 영향을 줄 때 조사한다. 순수 창작 설정과 내부 설계 선택을 외부 사실처럼 조사할 필요는 없다.

## 조사 순서

1. 질문을 의사결정 단위로 나눈다.
2. 공식 사이트, 플랫폼 문서, 개발자 발표, 패치노트 등 1차 출처를 먼저 찾는다.
3. 산업 규모나 추정치는 신뢰할 수 있는 조사기관 또는 기업 공시로 교차 확인한다.
4. 플레이 경험과 커뮤니티 반응은 후기·포럼을 보조 근거로 사용한다.
5. 각 주장에 확인일과 출처를 연결한다.

## 근거 등급

| 등급 | 근거 | 사용 |
|---|---|---|
| A | 공식 문서, 인게임 데이터, 공시, 플랫폼 정책 | 사실로 기술 |
| B | 신뢰할 수 있는 전문 매체·연구기관, 복수 출처 일치 | 사실로 기술하되 범위 명시 |
| C | 검증된 가이드·커뮤니티 위키·발표 요약 | 보조 근거 |
| D | 개별 후기·포럼 의견 | 정성 신호로만 사용 |
| E | 역산·추론·가정 | `추정` 또는 `가정` 표기 |

## 문서 분리

- **사실**: 출처가 직접 지지하는 내용
- **해석**: 사실에서 도출한 의미
- **제안**: 프로젝트에 적용할 설계 선택

한 문장에서 세 층위를 섞지 않는다.

## 출처 항목

`sources`에 다음을 기록한다.

- 읽은 페이지의 구체적인 제목
- 원문 URL
- 확인 날짜
- 문서에서 사용한 용도

검색 결과 페이지나 홈페이지만 연결하지 않는다.

## 불확실성

- 단일 추정치보다 범위와 계산 방식을 제시한다.
- 서로 다른 출처가 충돌하면 둘 다 기록하고 채택 기준을 설명한다.
- 확인할 수 없는 숫자는 삭제하거나 `미확인`으로 남긴다.
- 경쟁작 기능을 그대로 복제하라는 결론 대신 트레이드오프를 설명한다.
