# 데이터·기술 협업 기획서 kind

이 영역은 다른 kind의 결정을 기획 데이터, 테스트 가능한 규칙, 관찰 계획, 예외 결과로 정리한다. 새로운 게임 규칙이나 밸런스 목표를 임의로 만들지 않으며 물리 구조와 처리 방식은 `개발 협의 조건`으로 분리한다.

| 기획서 / kind ID / profile | 목적·주 독자 | 반드시 답할 결정 | 필수 산출물 | 기본 제외 | 인접 문서 핸드오프 | 완료 조건 |
|---|---|---|---|---|---|---|
| 데이터 테이블 정의서<br>`data-table-spec`<span id="data-table-spec"></span><br>`system` | 캐릭터·아이템·스킬 등 기획 데이터의 의미·관계·검증 기준 정의<br>시스템·콘텐츠·밸런스·데이터·QA 기획 및 개발 협업 담당 | 각 데이터 항목의 식별자, 의미, 단위, 기본값, 허용 범위, 관계와 버전 변경 영향은 무엇인가? | 테이블 목록, 데이터 항목 사전, 식별자·참조 관계, 예시 행, 기획 검증 규칙, 버전 호환 요구사항 | 게임 의미 규칙 결정, 최종 밸런스 승인, 로그 수집 구현, 물리 컬럼·타입·인덱스·저장 구조 | 입력: 모든 데이터 생성 kind<br>출력: 구현 데이터, `logging-spec`, `update-spec` | 기획 검증으로 누락·중복·잘못된 참조를 탐지하고 버전별 해석 기준이 있으며 물리 구조·변환 방식은 개발 협의 조건으로 남는다 |
| 로직·규칙 정의서<br>`logic-rule-spec`<span id="logic-rule-spec"></span><br>`system` | 자연어 규칙을 테스트 가능한 조건·상태·결과로 형식화<br>시스템·콘텐츠·데이터·QA 기획 및 개발 협업 담당 | 어떤 조건·우선순위·상태에서 어떤 게임 결과와 사용자 피드백이 발생하는가? | 규칙 ID 표, 조건·결과·우선순위, 상태 전이, 결정·진리표, 예시·반례, 의존 규칙 | UI 표현, 밸런스 목표·튜닝, 알고리즘·내부 처리·클라이언트/서버 순서 | 입력: 대상 시스템 kind<br>출력: `data-table-spec`, `exception-spec`, 구현·QA 케이스 | 같은 입력 상태의 기획 결과가 하나로 결정되고 경계값·동시 조건을 테스트할 수 있으며 구현 알고리즘은 개발 협의 조건으로 남는다 |
| 로그 기획서<br>`logging-spec`<span id="logging-spec"></span><br>`system` | 사용자 행동과 게임 결과의 관찰 계획 정의<br>데이터 분석·라이브·서비스·QA 기획 및 개발 협업 담당 | 어떤 행동·상태·결과를 어느 발생 조건에서 어떤 맥락 값과 함께 관찰해야 하는가? | 이벤트 분류·명명, 기획 속성 사전, 발생 조건 매트릭스, 대상·세션·맥락 정의, 중복·누락 검증 시나리오, 예시 이벤트 | 게임 규칙, KPI 목표 수치, 대시보드 시각 디자인, 원문 개인정보, 물리 페이로드·수집·저장·전송 방식 | 입력: 관측 대상 kind<br>출력: `live-ops-plan`, `game-economy`, QA·분석 파이프라인 | 핵심 퍼널·성공·실패를 기획 속성으로 재구성하고 중복·누락을 검증할 수 있으며 수집 방식은 개발 협의 조건으로 남는다 |
| 예외사항 정의서<br>`exception-spec`<span id="exception-spec"></span><br>`system` | 중단·경합·부족·반복 등 비정상 경로의 사용자 결과와 상태 복구 기준 정의<br>시스템·운영·QA·CS 기획 및 개발 협업 담당 | 접속 종료, 재시도, 반복 요청·수령, 인벤토리 부족, 동시 변경 시 사용자가 무엇을 보고 게임 상태·보상은 어디까지 유지·복원되는가? | 예외 매트릭스, 판정 조건, 실패 사유 분류, 재시도·반복 입력의 기대 결과, 복원 목표, 사용자 안내 키, 운영 에스컬레이션 | 정상 흐름 복제, UI 시각 디자인, 인프라 아키텍처, 트랜잭션·멱등·롤백 구현 방식 | 입력: 대상 시스템 kind, `logic-rule-spec`<br>출력: `ui-spec`, `logging-spec`, `update-spec`, QA 체크리스트 | 각 고위험 실패에 판정 조건·사용자 결과·게임 상태 목표·복구 기준·관찰 항목·담당이 지정되며 보장 방식은 개발 협의 조건으로 남는다 |
