# 기획 깊이 기준

분량 대신 독자가 실제 상황의 결과를 판정할 수 있는지로 깊이를 평가한다. 아래 공통 기준과 현재 profile 부분만 압축 작성 계약에 포함한다. 문서 종류의 소유 범위와 사용자가 요청한 간략함이 우선한다.

## common

- 핵심 결정마다 플레이어 목표 → 선택한 규칙 → 선택 이유와 감수하는 비용 → 관찰 가능한 검증 기준을 연결한다. 결과를 바꾸는 대안이 있을 때만 채택·기각 이유를 짧게 비교한다.
- 핵심 규칙은 적용 대상·전제조건·입력·조건별 결과·우선순위·종료 조건을 명확히 한다. 자원·보상·진행도가 바뀌면 소비·지급 시점과 실패·취소 시 보존 대상을 적는다. 복합 조건은 결정표, 시간에 따라 달라지는 규칙은 상태 전이로 설명한다.
- 대표 정상 사례와 결과가 달라지는 경계·실패 사례를 구체적 입력과 예상 결과로 대입한다. 중복 입력·동시 조건·중단·재진입·악용 중 실제 적용되는 사례를 선택하고, 본문 규칙만으로 답할 수 없는 사례는 규칙을 보완한다.
- 수치는 단위·적용 구간·출처 또는 설계 가정·산식·상하한·반올림을 필요한 만큼 명시한다. 계산 예시의 입력·중간 계산·결과를 재계산하고, 핵심 변수 변화가 목표 경험에 주는 영향을 비교한다. 미정값을 숨긴 확정값으로 채우지 않는다.
- 수용조건은 시작 상태·행동·관찰 결과로 쓴다. '재미있게', '적절하게', '정상 처리'를 검증 기준으로 끝내지 않는다. 미정 결정은 영향받는 규칙과 결정에 필요한 근거를 적고 검토 대상으로 남긴다.
- 본문과 도식·QA가 같은 규칙을 다루면 정상 사례와 결과가 갈리는 입력을 각각 따라가 상태·비용·보상의 끝값을 대조한다. 다른 문서의 결정은 실제 참조 또는 미제공 상태로 표시한다.
- 규칙을 다른 표나 문단에 반복해 깊이를 늘리지 않는다. 섹션에 적용되지 않는 기준은 억지로 채우지 않고, 관련 항목을 기존 섹션의 표·수식·사례·수용조건에 통합한다.

## concept

대표 플레이 한 회를 상황·선택·피드백·다음 목표까지 서술한다. 핵심 재미 가설이 어떤 선택에서 드러나는지, 대체 콘셉트 대비 차이와 위험이 무엇인지, 가장 작은 프로토타입에서 무엇을 관찰해 유지·변경할지 연결한다. 상세 시스템 수치를 임의로 확정하지 않는다.

## system

핵심 행동의 진입·진행·성공·실패·중단·재진입을 따라 조건과 보존 대상을 결정한다. 여러 규칙이 동시에 맞으면 우선순위를 정하고 정확히 하나의 결과가 나오는지 확인한다. 정상 사례와 경계 사례에 같은 규칙을 적용해 소비·지급·진행 결과를 계산한다.

## ui-ux

화면 상태별 진입 조건·가능 행동·비활성 이유·표시값·피드백·다음 상태를 연결한다. 로딩·빈 상태·오류·중복 입력·취소·복귀 중 관련 경로를 다룬다. 시스템 수치는 소유 문서에서 참조하고 표시·반올림·갱신 시점만 UI 범위에서 결정한다.

## content

한 콘텐츠를 입장·진행·완료·실패·반복까지 실제로 구성한다. 해금 조건, 플레이어 선택, 변주 축과 재활용 한계, 보상 자격을 구분한다. 대표 콘텐츠와 예외 콘텐츠에 생성 규칙·완료 판정·검수 기준을 대입한다.

## balance

목표 경험을 측정 지표와 연결하고 기준 대상·조건을 고정한다. 공식·계수·단위·상한·반올림으로 기준점과 경계값을 재계산한다. 주요 변수 변화와 우세 전략·성장 구간 역전 여부를 비교한다. 가정 데이터와 실측을 구별하며 차트·표·예제가 같은 값을 쓴다.

## economy

동일 기간·플레이어 유형 기준으로 핵심 자원의 유입·소비·잔고를 계산한다. 반복 수급과 일회성 보상을 구분하고 부족·포화·교환 순환·중복 지급을 검토한다. 조정 가능한 변수와 플레이어 부담, 목표 도달 시간의 관계를 수치 가정과 함께 설명한다.

## level

공간별 목적·동선·선택·도전·피드백을 연결한다. 의도한 경로와 우회·역주행·실패 복귀 경로를 따라 진행 불가 지점을 점검한다. 체크포인트와 자원 배치의 이유를 적고 플레이테스트에서 확인할 행동을 지정한다.

## narrative

인물의 욕구·갈등·선택·결과를 장면과 플레이 행동에 연결한다. 분기 조건과 합류 후 유지되는 사실, 정보 공개 순서, 설정 제약을 명시한다. 대표 장면 또는 대사 사례로 인물 말투와 설정 일관성을 검토한다.

## live-ops

대상·기간·참여·집계·보상·종료의 시점을 분리하고 시간대와 경계 참여의 판정을 명시한다. 지연·중단·재개·중복 수령의 플레이어 결과, 조정·중단 판단 지표와 담당을 정한다. 종료 직전 참여와 종료 후 재접속 사례를 검토한다.

## production

산출물·담당·선행 조건·완료 증거를 일정과 연결한다. 가용 인력·작업량·병렬 가능성의 가정을 드러내고 지연 시 영향받는 마일스톤을 계산한다. 축소 가능한 범위와 필수 품질, 검수 실패·재작업의 처리 기준을 구분한다.

## business

시장 사실·사업 가정·설계 제안을 구분한다. 대상 고객의 선택 이유와 경쟁 대안, 비용·수익·기간의 계산 근거를 연결한다. 불확실한 핵심 변수별 시나리오와 계속·보류 판단 조건을 제시한다. 외부 사실은 실제 근거가 있는 경우에만 확정한다.

## full

핵심 플레이 한 회를 시스템·콘텐츠·성장·경제·UI로 따라가며 각 단계의 입력·결과·연계를 대조한다. 공통 용어·자원·진행 조건의 모순을 제거하고, 상세는 소유 섹션 또는 실제 연결 문서에 한 번만 정의한다. 출시 범위와 검증 전제의 미정을 구분한다.

## review

작성 후 생성 지시를 되풀이하지 말고 실제 본문을 읽어 `working/<document>-review.json`에 짧게 기록한다. 내부 검토 파일은 HTML 원본 JSON에 넣지 않는다.

**같은 규칙이 여러 곳에 표현된 경우.** 신규 작성은 핵심 규칙, 수정은 변경된 규칙과 그 파생 결과를 대상으로 한다. 정상 사례 하나와 결과가 뒤집히는 경계·경합 사례를 고른다. 예를 들어 비용은 충분해도 완료 직전에 대상이 사라지면 차감 여부가 달라진다. 시작 상태, 시점, 행동을 고정하고 본문의 우선순위, 도식의 화살표, QA의 합격 조건을 각각 독립적으로 따라간다. 각 표현에서 도출한 최종 상태와 자원 변화를 같은 짧은 표기로 기록한다. 결과가 다르거나 필요한 분기·합격 조건을 찾을 수 없으면 해당 블록을 보완하고 다시 대입한다.

이때 검토 JSON의 `scenarios` 배열에 아래와 같이 기록한다. 경로는 해당 결과를 뒷받침하는 실제 문자열, 인용은 해당 문자열의 일부여야 한다. 도식이나 QA가 문서 범위 밖이면 해당 항목에 `{"out_of_scope": "범위 사유"}`를 쓴다. 범위 안의 분기 누락은 수정 대상으로 남긴다. 규칙을 한 곳에서만 다루는 문서는 기존 의미 검토를 사용한다.

```json
{"scenarios":[{
  "input":"구매 확인 직전 잔고 9개, 가격 10개, 확정 입력",
  "rule":{"path":"/sections/0/blocks/0/rows/1/2","quote":"잔고 부족이면 거절하고 보유량을 유지한다","outcome":"거절, 잔고 9개"},
  "diagram":{"path":"/sections/1/blocks/0/code","quote":"부족| F[구매 거절 · 소비 없음]","outcome":"거절, 잔고 9개"},
  "qa":{"path":"/sections/2/blocks/0/rows/0/2","quote":"거절 표시, 잔고 9개","outcome":"거절, 잔고 9개"}
}]}
```

렌더 후 기존 검증 명령에 `--scenario-review working/<document>-review.json`을 추가한다. 도구는 전달할 HTML의 편집 원본에서 인용을 찾고 기록된 결과를 대조한다. 인용이 해당 입력의 결과를 뒷받침하는지는 작성자가 실제 분기를 따라 확인한다.

```json
{
  "verdict": "pass|repair|needs-decision",
  "checks": [
    {"criterion": "핵심 행동 판정", "evidence": ["/sections/2/blocks/0"], "result": "pass", "reason": "정상·경계 입력에 대한 결과가 규칙표와 일치"}
  ],
  "issues": [
    {"path": "/sections/2/blocks/0", "problem": "충돌하는 조건 또는 누락", "impact": "판정할 수 없는 상황", "repair": "필요한 결정"}
  ]
}
```

핵심 결정 근거, 조건·우선순위, 예외·보존, 수치 계산, 수용조건, 문서 내·간 일관성을 적용 가능한 범위에서 검토한다. 근거 경로는 실제 내용이어야 한다. 비적용은 범위 사유를 적는다. 수치가 있으면 스크립트·계산기로 다시 계산한다. 모든 정상·경계 사례의 결과를 본문만으로 설명할 수 있고 미해결 중대 모순이 없을 때 `pass`로 판정한다. 사용자 결정이 필요한 내용은 가정 또는 미정으로 표시하고 영향과 함께 전달한다. HTML 자동 검증 통과를 기획 내용 검토 통과로 취급하지 않는다.
