# 운영·마케팅 관련 기획서 kind

단기 이벤트, 상시 라이브 운영, 상품 노출 캠페인, 버전 변경 전달을 분리한다. 영구 시스템 규칙과 SKU 정의는 각각 원 소유 kind를 참조한다.

| 기획서 / kind ID / profile | 목적·주 독자 | 반드시 답할 결정 | 필수 산출물 | 기본 제외 | 인접 문서 핸드오프 | 완료 조건 |
|---|---|---|---|---|---|---|
| 이벤트 기획서<br>`event-plan`<span id="event-plan"></span><br>`live-ops` | 기간 한정 참여·보상·운영 절차 정의<br>라이브·콘텐츠·CS·QA 기획 및 개발 협업 담당 | 언제 누구에게 어떤 미션·규칙·보상을 열고 장애·종료·정산 상황에서 어떤 사용자 결과와 운영 대응이 필요한가? | 기간·대상, 참여·진행·종료 규칙, 미션·보상 연결, 운영 타임라인, 점검·중단·복구 기준, QA 조건 | 영구 시스템 상세, 보상 최종 산정 근거, 상품 홍보 문안, 장애 복구 구현 방식 | 입력: `content-design`, `reward-design`<br>출력: `live-ops-plan`, `ui-spec`, `logging-spec`, `exception-spec` | 시작·변경·종료·보상 정산·장애 상황별 사용자 결과와 운영 판단 기준이 있고 보장 방식은 개발 협의로 남는다 |
| 라이브 운영 기획서<br>`live-ops-plan`<span id="live-ops-plan"></span><br>`live-ops` | 업데이트·시즌·반복 콘텐츠 운영 체계 설계<br>라이브 디렉터, 운영·개발·데이터·CS | 어떤 주기로 무엇을 로테이션하며 어떤 지표·임계치로 조정·중단·복구하는가? | 시즌·업데이트 로드맵, 콘텐츠·상품 로테이션, 운영 캘린더, 역할·승인, 모니터링 지표·임계치, 사고 대응 | 개별 기능 명세, 개별 이벤트 상세, 마케팅 크리에이티브 | 입력: `event-plan`, `product-promotion`, `logging-spec`<br>출력: `development-plan`, `update-spec`, 다음 `event-plan` | 각 운영 슬롯에 소유자·선행 조건·관측 지표·판단 시점·대응안이 있다 |
| 상품 프로모션 기획서<br>`product-promotion`<span id="product-promotion"></span><br>`live-ops` | 상품의 대상·메시지·노출·실험 설계<br>사업·마케팅·라이브·UI·데이터 팀 | 누구에게 어떤 제안과 메시지를 어느 채널·빈도·기간으로 노출하고 효과를 어떻게 비교하는가? | 캠페인 브리프, 세그먼트·자격, 노출 위치·일정·빈도, 할인·메시지 요구, A/B 셀, 성과 이벤트·중단 기준 | SKU 구성·정가·구매 로직, 결제 구현, 최종 크리에이티브 자산 | 입력: `store-product`, `game-economy`<br>출력: `ui-spec`, `live-ops-plan`, `logging-spec` | 대상·오퍼·노출·대조군·성과 판정이 연결되고 과노출·오표시 방지 조건이 있다 |
